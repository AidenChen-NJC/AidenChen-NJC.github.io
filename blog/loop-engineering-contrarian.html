Loop Engineering

X 上的新敘事：別再逐句 prompt，去寫那個會替你 prompt 的 loop。但邏輯不太對 — loop 本身只是 while true，免費，而且會把單步錯誤指數放大。真正稀缺的不是迴圈，是讓它跑歪也賠不多的那層約束面。

自主性不只是自動化，而是槓桿，風險也被放大。
真正稀缺的是「喊停修正」的能力。
做對的人不是寫更漂亮的 loop。是建一個「就算 loop 跑歪、也賠不多」的約束面。

一、Loop 是什麼

最近 X 上有一條敘事越來越紅：你不該再逐句 prompt coding agent，你該去設計那個會替你 prompt agent 的 loop。Addy Osmani 命名為 “Loop Engineering”。Boris Cherny 也說他現在不 prompt Claude 了，他寫 loop，由 loop 去 prompt Claude。

層級是：

Prompt engineering   → 你送出的「字」
Context engineering  → 模型看得到的「全部資訊」
Harness engineering  → agent 跑的「環境」（tools / sandbox / hooks / recovery）
Loop engineering     → 驅動 agent 朝目標跑的「迭代循環」

loop = 一個遞迴目標。定了目標後，agent 自己接收 → 思考 → 行動 → 觀察結果 → 重複直到一個「可驗證的停止條件」成立。

二、Loop 的底層邏輯

底層就是 ReAct（Reason + Act）：想一步、做一步、看結果、再想。Loop engineering 只是把這個 cell 接上三件外掛：

  • State：記憶寫在 context 之外（跨 session 還是能用）。
  • Verifier：另一個用於打分驗證結果的模型。
  • Termination：step ceiling、token budget、stall detection, etc。

所以「loop engineering 是新典範」這個敘事，底層其實是一句話：槓桿從「寫好一句 prompt」變成「設計那個會一直 prompt 的控制系統」。

真正在賣的情緒是：What if 我們可以把「人」這個 bottleneck 從迴圈裡抽掉？

三、Loop 的價值在哪裡

假設每步 AI 產出是 95% 正確、跑 20 步，端到端正確率只剩 36%：

0.9520 ≈ 0.36

這是錯誤率的複利效應。模型把自己上一步的錯誤讀進 context，會更容易在下一步沿用它。Step 3 出錯了，step 4 在污染過的 context 上跑，step 5 在「污染 + step 4 新增的污染」上跑。

大眾把「自主性」當成價值來源。但是自主性本身不產生價值。

while true 是免費的。任何人三行寫得出來。稀缺的從來不是迴圈，是迴圈裡真的有用的 termination，以及一個真的會看見錯誤的 Verifier。

反過來：一個 loop 呼叫的是被測過、可以重複使用的 skill，那才會複利。價值在 skill 與 verifier，不在 loop。

四、怎麼正確的使用 Loop

多數人先寫 loop 再想驗證，但我認為應該相反。

  1. 可驗證性是前提，不是功能。 寫不出 checkable 成功條件，就別 loop。確定性目標好辦（tests pass / CI green / lint clean）。模糊目標（“build this feature”）先寫 spec，把「done 長什麼樣」寫死。這步才是 loop engineering 真正難、也真正值錢的地方。
  2. 先手動做。 你自動化不了你描述不出來的東西。挑一個你團隊常做的無聊流程，自己跑三遍，把你「沒意識到自己在做」的決策寫下來。那份筆記就是你的 skill。
  3. 單 agent、單流程、單可量測結果先過。 別一開始就上五個 agent 平行。三個 70% 串起來是 34%，先證明「一個」在你真實環境穩，再展開。
  4. Verifier 和 Termination 設好。 我自己有一個 agent 專門攻擊我開發的工具，抓出自己的漏洞。
  5. Global level 的 lessons.md。 建立一個 global 以及 project level 的學習迴圈，把每次 debug 的內容、Claude 常犯的錯誤寫進 lessons.md，讓每次都持續學習、並套用之前學到的點。
